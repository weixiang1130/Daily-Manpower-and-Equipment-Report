# 節點 25 — 工程師叫工排名報表（v19）

## 背景

工地月結需要一張「各工程師叫工統計排名表」（沿用既有 Excel 慣用版式）：列＝工種（含該工種總工數），欄＝排名 1..N（工程師＋工數），統計哪位工程師叫了什麼工種、人數多少並排名。系統已有全部原始資料（回報的 engineer 與逐工種 workTypes），缺的是彙總視圖與匯出。

## 口徑（使用者裁示，2026-07-31）

- **總工數＝Σ出工數＋Σ(加班前2h＋第3h起)÷8**（8 小時折 1 工）；排名依折算後總數
- 僅計已回報單；期間與廠商篩選連動
- v11 前無逐工種明細的舊單：以 actual＋totalOT÷8 歸入「（未分工種）」列，確保不漏計

## 變更內容

- 歷程報表新增第三個頁籤「叫工排名」（rtab data-r="ranking"）
- `buildRankingData()`：彙總 工種→工程師→折算工數；`renderRankingReport()`：畫面表格（排名合併顯示「名字（工數）」）；`exportRankingXls()`：帶格式 .xls 匯出
- 排名報表模式下隱藏無關的內容/工程師篩選與計價彙總鈕，匯出鈕文字切換；切回明細報表自動恢復
- 期別標示：期間同月→民國「YYY.M」（如 115.6），否則顯示起訖
- .xls 為 HTML 表格格式（Excel 直接開啟）：期別欄 rowspan、表頭 colspan 雙欄群組、mso-number-format 數字格式、仿附表底色——零外部套件，維持無依賴原則

## 影響範圍

- `index.html`（一顆 rtab）、`app.js`（彙總/渲染/匯出＋renderReport 分支）；後端／合約／SQL：零修改

## 驗證紀錄

- DEMO 可驗算資料集：3 工程師 × 3 工種含加班——粗工總數 19.75（10.5/8.25/1，含 4h→0.5 工折算）、技術工 10.5（丙 7.5＞甲 3）、舊制單 fallback 歸（未分工種）5；排名與列序全部正確
- 匯出 XLS 攔截驗證：民國期別 115.6、rowspan/colspan 結構、排名表頭 3 組、底色與數字格式齊備
- 廠商篩選連動（篩後只剩該廠商資料）、切回明細報表 UI 恢復、console 零錯誤

## v19.1 修正（2026-07-31，上線當日口徑修正）

- **口徑改為純出工數**：使用者澄清「工數是計價時換算的」——加班折算屬計價階段，報表只抓實際回報的工種出工數（可含 0.5）。移除 ÷8 折算
- **「（未分工種）」列取消**：實查正式資料，無 workTypes 的已回報單共 18 筆，多為 0 工單（本就不進排名）；有工數者其申請單「工作內容類別」即為工種資訊（打石、鋼筋作業等）——fallback 列名改用 categories join，顯示實際回報內容
- 驗證：粗工 19.5＝10＋8.5＋1（加班不計入）、0.5 工保留、fallback 列名「打石、鋼筋作業」、0 工單不出現、console 零錯誤

## v19.2 補強（2026-07-31，主管需看加班時數）

- **需求**：使用者說明「工數目前是用 8 小時換算，需要分為 本工／加班前2個小時／2小時後的加班／總工數，主管需要看加班時數」——這也解釋了原始附表「291.1948」這類四位小數：總工數確實含加班折算，v19.1 之所以被糾正是因為只給一個折算後數字、看不到加班
- **欄位**：本工（work）／加班前2h（ot2 時數）／加班2h後（otOver 時數）／總工數＝本工＋(ot2+otOver)÷8；排名依總工數
- **版面改縱向**：四個數值欄橫向排不下（原「排名N/工數」兩欄一組會變五欄一組），改每位工程師一列＋工種小計列；對主管掃視加班、對後續樞紐分析都較佳
- 匯出 Excel 同結構並補「加班合計(時)」欄；工種欄 rowspan 合併、小計列米色底
- 驗證：10+4/8=10.5、8.5+2/8=8.75、6+12/8=7.5、舊制單 4+8/8=5（加班歸前2h 段）；小計 19.5/4/2/20.25；XLS 八欄表頭、rowspan、三個小計列、底色與數字格式；console 零錯誤
