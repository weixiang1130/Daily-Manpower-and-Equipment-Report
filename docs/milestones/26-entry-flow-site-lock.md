# 節點 26 — 開站動線優化（v20）＋帳號權限規畫

## 背景

使用者指出開站動線「雞肋」：攔截頁已選過一次工地，卻仍停在總覽頁，要工作還得再點一次——等於選兩次。並提出未來方向：帳號權限管控（連動 AD），屬於某專案的人只能看到、只能更動該專案。裁示「先規畫，能做的先做」。

## 變更內容（前端能先做的）

- **enterSite() 直進點工頁**：選定工地即 switchMainTab("labor")，消除二次點擊
- **單站自動進入**：MASTER.sites 僅 1 站時免選直進——AD 過濾後單站使用者零點擊直達
- 修正設定頁過時提示（v17 起新工地零種子名單）

## 設計決策：不做「一站一連結」（使用者裁示）

初版曾實作 URL 鎖站模式（`?site=` 免選站＋隱藏切換器與總覽）與管理員專屬連結產生器，使用者裁示於部署前移除：**權限系統上線前維持自由跳轉**，工地可見性隔離一步到位交給 API 層權限過濾（見 AUTH-PLAN §3）——避免過渡期出現「看似隔離、實則可繞過」的中間態，也少維護一套發連結的流程。

## 權限規畫（docs/AUTH-PLAN.md，交資訊處）

四角色（工地使用者/成控稽核/系統管理者/唯讀）、AD 群組制（建議）vs DB 對映表、API 層過濾六要點（scope=all 過濾、site 403、audits 剝除、破壞性 op 限管理者、操作 log、移除 Basic Auth）、推進順序。API 合約格式不變（權限過濾屬合約允許的強化）。

## 影響範圍

- `index.html`（連結面板＋提示修正）、`app.js`（init 分支/enterSite/applyLockedSiteUI/連結產生複製）；後端／合約／SQL 零修改
- 新增 `docs/AUTH-PLAN.md`；`docs/MIGRATION-PLAN.md` 連結

## 驗證紀錄

- DEMO：選站後直達點工頁；右上切換器與總覽維持正常（自由跳轉）；`?site=` 參數不再有作用；單站自動進入分支保留；console 零錯誤
