# 節點 28：閒置逾時與登出（v22）

## 背景

資訊處提出：系統未設自動登出，建議 **10 分鐘閒置 timeout**，並要有**使用者可
點的登出按鈕**。工地現場常有共用電腦，管理員登入後走開即為風險。

## 作法

- **閒置逾時**：記「最後操作時間」（pointerdown/keydown/wheel/touchmove/scroll，
  capture＋passive），每 30 秒檢查一次；閒置滿 10 分鐘（`IDLE_LIMIT_MS`）即登出。
  分頁回前景（visibilitychange）立即補查——掛過夜的分頁一回來就登出，
  不依賴背景計時器（瀏覽器會節流背景分頁的 timer）
- **登出按鈕**：頁首右上（重新整理旁）。confirm 提醒會清除未送出的表單內容，
  確認後執行相同的登出流程
- **登出＝**清除 sessionStorage（`dm_site`/`dm_admin`）→ 設原因旗標 → `location.reload()`
  ——重用既有開機路徑回到選站畫面，管理員模式同時失效；reload 後依旗標
  toast 顯示「閒置自動登出」或「已登出」
- 載入完成前（`READY=false`）不計時，避免慢速網路開站途中被誤登出

## 過渡期範圍限制（誠實聲明）

Basic Auth 帳密由瀏覽器保存，**無法用程式清除**——本機制清除的是本分頁的
工作狀態與管理員模式（實際的防護目標）；要讓瀏覽器忘記帳密需關閉瀏覽器。
地端 SSO 上線後，登出改為丟棄 token（AUTH-PLAN §4），本機制直接沿用。

## 驗證（本機實測，非模擬）

- 閒置觸發：把最後操作時間撥回 11 分鐘 → 檢查觸發 → 頁面實際 reload、
  `dm_site`/`dm_admin` 已清、旗標已消費、toast「閒置超過 10 分鐘…」正確顯示
- 操作監聽：dispatch pointerdown 後最後操作時間確實更新
- 登出按鈕：取消 → 狀態原封不動；確定 → 清除＋reload＋toast「已登出…」
- console 零新增錯誤（僅本機無 /api 的既有 404）
