# 節點 28：閒置逾時與登出（v22）

## 背景

資訊處提出：系統未設自動登出，建議 **10 分鐘閒置 timeout**，並要有**使用者可
點的登出按鈕**。工地現場常有共用電腦，管理員登入後走開即為風險。

## 作法

- **閒置逾時**：記「最後操作時間」（pointerdown/keydown/wheel/touchmove/scroll，
  capture＋passive），每 30 秒檢查一次；閒置滿 10 分鐘（`IDLE_LIMIT_MS`）即登出。
  分頁回前景（visibilitychange）立即補查——掛過夜的分頁一回來就登出，
  不依賴背景計時器（瀏覽器會節流背景分頁的 timer）
- **登出按鈕**：頁首右上（重新整理旁）。confirm 提醒會清除未送出的表單內容，
  確認後執行相同的登出流程
- **登出＝**清除 sessionStorage（`dm_site`/`dm_admin`）→ 設原因旗標 → `location.reload()`
  ——重用既有開機路徑回到選站畫面，管理員模式同時失效；reload 後依旗標
  toast 顯示「閒置自動登出」或「已登出」
- 載入完成前（`READY=false`）不計時，避免慢速網路開站途中被誤登出

## 過渡期範圍限制（誠實聲明）

Basic Auth 帳密由瀏覽器保存，**無法用程式清除**——本機制清除的是本分頁的
工作狀態與管理員模式（實際的防護目標）；要讓瀏覽器忘記帳密需關閉瀏覽器。
地端 SSO 上線後，登出改為丟棄 token（AUTH-PLAN §4），本機制直接沿用。

## 驗證（本機實測，非模擬）

- 閒置觸發：把最後操作時間撥回 11 分鐘 → 檢查觸發 → 頁面實際 reload、
  `dm_site`/`dm_admin` 已清、旗標已消費、toast「閒置超過 10 分鐘…」正確顯示
- 操作監聽：dispatch pointerdown 後最後操作時間確實更新
- 登出按鈕：取消 → 狀態原封不動；確定 → 清除＋reload＋toast「已登出…」
- console 零新增錯誤（僅本機無 /api 的既有 404）

## v22.1 修正（2026-08-05，code review max）

閒置登出初版有四個缺陷，全部修復：

| 問題 | 修法 |
|---|---|
| **編輯中也會逾時登出**，靜默清掉已填的逐工種列與查核回饋（手動登出有 confirm 提醒，自動路徑沒有） | `idleCheck` 加 `anyEditing()` 守衛——與整批刷新同一組（架構不變式 1），編輯中延後一輪再查 |
| `dm_auditor`（上一位稽核人員**真實姓名**）未清除 | 共用平板上下一位會以前一位名義送出稽核；登出清除清單加入該鍵 |
| **單一工地時登出等同無效**——`boot()` 的自動進入立刻把人放回站內，還會每 10 分鐘 reload 一次 | 剛登出這一輪跳過自動進入（權限上線後「只看得到一站」正是常態） |
| `#logoutBtn` 無 null 檢查、sessionStorage 未包 try/catch | 舊 index.html 配新 app.js、或 Safari 無痕，會讓整個 DOMContentLoaded 中斷 → 卡在載入畫面且不會顯示錯誤頁；改為容錯 |

## v22.2 修正（2026-08-05，xhigh 審查：v22.1 的守衛本身有兩個反向錯誤）

v22.1 為了「編輯中不要清掉輸入」加的 `anyEditing()` 守衛，兩個方向都不對：

| 問題 | 說明 |
|---|---|
| **保護不到最常見的情況** | `editing*Id` 只在**編輯既有單**時設定（`loadXxxRecord`）。使用者新開一張申請單填到一半時四個旗標全是 null → 守衛失效 → 照樣被清掉。而「填新單填到一半」正是最常發生的 |
| **保護到的情況變成永不登出** | 命中守衛時做 `lastActivityAt = Date.now()`，等於每輪給一個全新的 10 分鐘。只要表單開著就**永遠不會登出**——資訊處要的共用平板防護完全失效（註解寫「延後一輪」，但實作是重新計時） |

**改法**

- 新增 `hasUnsavedInput()`：直接掃四個表單面板＋稽核表單＋設定頁的
  input/textarea/select 與動態產生的工種列／標籤／附件格。不再依賴
  `editing*Id`，新表單一樣受保護
- 寬限時**不重置 `lastActivityAt`**：表單一送出或清空，下一個 30 秒 tick
  就立即登出
- 新增 `IDLE_HARD_LIMIT_MS = 30 分`絕對上限：放超過半小時的表單已非
  「正在填」，共用平板留著管理員 session 的風險大於那份內容

**sessionStorage 容錯全面套用**：v22.1 只在登出路徑加了 try/catch wrapper，
其餘 10 處仍是裸呼叫——Safari 無痕下 `enterSite` 會在 `READY=true` 前拋錯
（開站卡死）、`isAdmin` 每次 renderAll 都會拋。現已全部收斂到
`ssSet/ssGet/ssDel`，wrapper 移到檔案前段並註明「新增存取點勿直接呼叫」。

**驗證（本機五情境實測）**

| 情境 | 結果 |
|---|---|
| 空白閒置 11 分 | 登出 ✅ |
| 新表單填一半、閒置 11 分 | 不登出 ✅（同時確認舊守衛 `anyEditing()` 為 false，證明舊版會清掉） |
| 寬限時 | 計時器未被重置 ✅ |
| 表單開著逾 30 分 | 強制登出 ✅ |
| 表單清空後 | 下一 tick 立即登出 ✅ |

計價迴歸：舊制單歸段 4/0、0 工帶加班 3/0、彙總前 2h＝7、`constructor`
工種正常成欄、匯出無例外——皆與 v22.1 一致。
