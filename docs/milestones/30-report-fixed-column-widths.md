# 節點 30：固定欄寬與長字串換行（v22.3 報表／v22.4 清單頁）

## 背景

使用者回報：歷程報表「欄位太多太長，加上現場查核回饋字數太多，導致整個版面要一直往右邊拉，
這樣導致版面不一致，且太長了」，並提出「將現場回饋字數用自動換行」的做法。

實測改前（點工明細，26 欄，其中一筆查核回饋 128 字）：

| 量測項目 | 改前 |
|---|---|
| 明細表寬度 | 4,525 px |
| 整頁內容寬度 | 4,599 px（視窗 1,440） |
| 「現場查核回饋」單欄寬度 | 1,748 px |

成因是全域 `th,td{white-space:nowrap}`：只要有一筆回饋寫得長，那一格就撐成一整列文字。
而 v16.1 把 `.table-wrap` 從內部捲軸改成 `overflow:visible`（為了讓表頭黏在頁籤下方），
所以被撐開的是**整頁**而非表格自己。加上 `table-layout:auto` 下欄寬由當頁最長那筆決定，
**翻頁時整個版面會跟著跳**——這就是「版面不一致」。

## 做法

### 1. 固定欄寬（`REPORT_COL_W`）

改用 `table-layout:fixed` ＋ `<colgroup>` 逐欄指定寬度，與叫工排名表（節點 25 / v19.4）同一招。
欄寬對照表以**表頭字串**為鍵，欄序調整時不必同步索引；未列出的欄位用 `DEFAULT_COL_W`。

寬度依實測訂定，而非估算：

- 日期欄 120 px —— 量到 `YYYY-MM-DD` 需要 118 px，先前給 96 會斷成兩行
- 人名欄 90 px —— 三字姓名不折行
- 數值／記號欄 58～70 px —— 內容只有個位數或一個 V，寬度其實由**表頭**決定
- 自由文字欄 100～220 px —— 讓它折成數行

### 2. 三個必要的配套

改成 fixed 版面後有三件事會出錯，缺一都會被使用者看見：

1. **欄寬不再自動長大**，所以 `.report-table` 的 th/td 必須**全部**放行換行
   （`white-space:normal` ＋ `overflow-wrap:anywhere`）。留任何一欄 nowrap，
   超寬內容就會直接壓到隔壁欄上。
2. **表格必須自帶總寬**。`table-layout:fixed` 若 `width` 為 auto，Chrome 會把 `<col>`
   的 px 值當成**比例**去縮放可用寬度——實測 26 欄被壓到每欄 34 px、單列高度 2,569 px。
   只有寫死總寬（欄寬加總）才會照設定值。
3. **面板底色與頁首色帶要跟著變寬**。兩者都是區塊元素，寬度只由容器決定，
   表格溢出的那半截原本落在頁面底色上——右半邊沒有白底、深色頁首也只到視窗邊，
   這是「版面不一致」的另一半。`min-width:min-content` 讓它們長到容納最寬的子元素為止；
   其中 `#app` 因為有 `max-width:1600px`（v15.3），必須靠 **min-width 依規範優先於 max-width**
   才推得動。三條規則都只在 `@media(min-width:901px)` 生效——窄螢幕是 `.table-wrap`
   自己橫捲，body 若跟著變寬會害整頁橫捲，等於把手機版一起拖下水。

## 驗證

| 量測項目 | 改前 | 改後 |
|---|---|---|
| 明細表寬度 | 4,525 px | 2,282 px |
| 整頁內容寬度（視窗 1,440） | 4,599 px | 2,356 px |
| 「現場查核回饋」欄寬 | 1,748 px | 220 px |
| 最長那列的高度 | 39 px（單行拉長） | 219 px（折 12 行） |
| 內容壓到隔壁欄的格子數 | — | 0 |
| 回饋全文是否完整顯示 | 是 | 是（128 字全在，未截斷） |

- **六種視窗寬度 × 五個頁籤 × 三個報表子頁**全跑過：`1920/1440/1280/1024/820/480`。
  820 與 480 走窄螢幕分支（`.table-wrap` 自己橫捲），整頁不橫向溢出，與改前一致。
- **未波及其他頁籤**：以「關掉本節點三條 min-width 規則」為基準逐頁對照，
  總覽／機具／設定三頁寬度完全不變；點工申請頁的橫向捲動**改前就存在**
  （其清單表同樣是 nowrap 撐寬），本次只多了 37 px 的 `#app` 內距，
  並順帶把該頁的頁首色帶補齊到內容右緣。
- **計價數字未受影響**：本次只改渲染，匯出走的是 `def.rows()` 與 `pricingSummaryTable()`，
  完全不經過新的表格產生器；彙總畫面數字改前改後逐格相同。
- 叫工排名表走自己的 `renderRankingReport()`，未套用新 class，版面不變。

## 已知取捨

26 欄的稽核明細**無法**在 1,440 視窗內完整放下（欄寬已壓到表頭下限）。
本節點把「隨資料變動、最長到 4,500 px」收斂為「固定 2,282 px」，
翻頁與換工地都是同一個版面，但寬螢幕仍需向右捲約 900 px。

若要進一步縮短，得動到欄位本身，屬於報表內容決策，待裁示：

- 把「根基自辦工數／時數／備註」三欄併成一欄顯示（廠商代辦同理），可省約 190 px
- 「人臉／白卡／工具箱紀錄」三欄併為一欄，可省約 90 px
- 或改為畫面只顯示常用欄位，完整 26 欄仍由匯出的 xlsx 提供

# v22.4 補強：清單頁一併套用

## 背景

v22.3 只改了歷程報表。使用者隨即回報：「申請跟回報那邊沒有改到，現場查核回饋那邊也是
太長了……有類似情形都優先採用自動換行，不要讓版面都變得要拉這麼長。」

**點工清單有同一個「現場查核回饋」欄**，症狀完全一樣——實測表寬 2,878 px、整頁 2,915 px。

## 全系統表格盤點

| 表格 | 處理 |
|---|---|
| 點工清單（點工申請/回報頁） | ✅ 本次套用——含現場查核回饋，問題最嚴重 |
| 機具清單（機具申請/回報頁） | ✅ 本次套用——類型／型號為自由文字 |
| 稽核紀錄清單（成控現場稽核頁） | ✅ 本次套用 |
| 歷程報表明細＋計價彙總 | ✔ v22.3 已處理 |
| 叫工排名 | ✔ v19.4 已是固定欄寬，走自己的 `renderRankingReport()` |
| 總覽跨工地 | ➖ 6 欄純數字、無自由文字，維持原樣 |
| 稽核 PDF 報告 ×2 | ➖ 另一份列印用 CSS，只有 `.info th` 與 `.w1` 是 nowrap（皆為短固定欄），資料格本來就會換行 |

## 變更

1. **機制抽為共用工具**並移到 `app.js` 上方（原本埋在「歷程報表」區塊，但已被三個區塊使用）：
   - `COL_W`（原 `REPORT_COL_W`）：全系統共用欄寬表，以表頭字串為鍵
   - `fixedTableOpen(headers, opts)`：產生 `<table>`＋`<colgroup>`＋`<thead>`，
     呼叫端只接自己的 `<tbody>`。**表頭與欄寬同一份來源**，不會各改各的而對不起來
   - `opts.actionW`：覆蓋「操作」欄寬（稽核紀錄的按鈕比清單頁少）
2. **CSS class 改名** `.report-table` → `.fixed-table`（已不只報表在用）
3. **`.panel{min-width:min-content}` 由 `#tab-history` 放寬為全部面板**，
   讓清單頁的面板底色也跟著表格右緣
4. **新增徽章與按鈕的 nowrap 例外**：`.fixed-table .tag/.btn-mini{white-space:nowrap}`。
   狀態徽章與操作按鈕是「一個物件」，字被拆行就散了；欄寬已在 `COL_W` 預留
   （狀態 78／操作 260），不需要靠折行擠

### 驗證過程中修掉的兩個誤判

1. **頁籤 id 打錯**：驗證腳本用 `equip`，實際是 `equipment`——所以 v22.3 那輪
   「機具頁寬度不變」等於**沒測到**，本次補測。
2. **「操作按鈕被擠成兩行」是假警報**：`.row-actions` 是 `<td>` 本身（`display:flex`），
   量它的高度抓到的是**整列高度**，長回饋讓列變高就一定超標。
   改判「同格內按鈕是否落在不同 y 座標」後全數通過。
