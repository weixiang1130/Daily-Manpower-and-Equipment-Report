# 節點 37：介面精簡、排名圖表化、計價暫時下架（v23.1）

## 背景

使用者盤點整個介面後提出三項：

1. 需要填寫的區塊佔太大版面，整體排版要更簡潔
2. 排名與相關數據盡量改以圖表呈現
3. 匯入行情通報的功能與計價模組**先拿掉**

## 變更內容

### 一、計價呈現開關（`PRICING_UI`）

**是畫面層的開關，不是功能移除。** 費率書、費率綁定、金額計算、SQL 的費率三張表、
地端 .NET 的對應實作全部原樣保留；改一個常數即整組回來。

關掉時隱藏：設定頁的行情通報匯入與綁定、機具回報的計價品項下拉、明細報表與
計價彙總的「計價金額／計價組成／未能計價單數」欄、兩張廠商排行榜的金額欄。

**刻意保留代辦扣抵金額**（使用者裁示）。代付代扣是會議點名要「由系統自動統計、
排除人工作業」的項目，一起關掉等於白做。它靠的是**已匯入的費率書**——費率書存在
後端（`rates:` 鍵，實查線上有 115Q3：租工 166 列、機具 1,499 列），不因匯入入口
隱藏而消失，所以照算。

> ⚠ **換季要匯入新費率時必須先把開關打開**——匯入入口也在這組裡面。

### 二、版面收斂

**先量再改。** 實測四張表單的高度組成後才發現：73～86% 的高度來自「滿版欄位」
（標籤挑選器、附件框、textarea、動態列表），而不是一般欄位的寬度。
一開始把一般欄位從 1/3 縮成 1/4，實測只省下 0～65px——**方向錯了，已回退**。

真正有效的三件事：

- 中等高度的滿版區塊改成一排兩個（`.field-half`）
- 動態列表區塊把「標籤＋加入控制」併成同一行（`.field-head`），冗長說明收進 `title`
- 縮小格線間距與標籤字級

其中**代辦區塊是兩張回報表單裡最高的元素**（258px／196px）——那是節點 36 剛加的，
標籤、空狀態框、加入控制、三行說明各佔一段。併行後降到 178px／135px。

### 三、排名圖表化

新增零依賴的橫向長條圖（`hBarChart`）：

- 廠商排名：點工榜、機具榜各一張圖
- 叫工排名：新增「各工程師叫工總量」圖——原本的表是逐工種分組，要回答
  「整體誰叫工最多」得自己心算跨工種加總，那正是總經理要看的數字

用 HTML/CSS 長條而非 SVG：長度只要一個百分比寬度就成立、天生隨容器縮放；
SVG 得靠 viewBox 換算，中文標籤與數值還要自己排版（第一版寫成 SVG，
`preserveAspectRatio="none"` 會讓長條變形，已改寫）。

依 UI 準則 §10：**圖不取代表**（下方一律保留原數值表）、每條直接標數值
（顏色不是唯一資訊來源）、`role="img"` ＋ 一句話 `aria-label`、只畫前 10 名
並在圖下明講「另有 N 項未列出」（不做無聲截斷）。

## 踩到的坑

**`const` 的暫時性死區（TDZ）。** `PRICING_UI` 一開始宣告在檔案中段，但 `REPORTS`
的欄位陣列是 top-level 物件字面值、載入當下就會讀它——整支 app.js 在載入階段
就中斷，畫面看起來只是「沒套用」。宣告已移到檔首並加註警語。

這也污染了第一次的版面量測：JS 全死時量到的高度沒有意義，一度以為改動讓版面
**變高**。之後改用 git HEAD 版本開 iframe 做 A/B，才拿到可信數字。

## 驗證

- **版面**（以 git HEAD 版本開 iframe 同寬度 A/B，1280px）：
  四張表單合計 **2,971 → 2,329px，省 642px（-22%）**；
  機具回報 -29%、點工申請 -24%、機具申請 -22%、點工回報 -13%
- **計價下架**：使用者實際看得到的文字裡已無「匯入行情通報」「計價金額」；
  `ratesPanel`／`e_rateItemField` 皆 `display:none`，但 `e_rateItem` 仍在 DOM
  （多處程式會讀它的值，真的拿掉會整支壞掉）
- **代辦扣抵仍運作**：乙廠商 12,000 ＝ 2 工×2000 ＋ 1 天×8000，與節點 36 相同
- **圖表**：叫工排名 工程師A 13.5 工（8＋5 工＋4h÷8）、工程師B 3 工，
  長條寬度 3÷13.5 ＝ 22.2%，比例正確；廠商榜 甲廠商 11.5 工／2 單
- **手機（375px）**：長條原本被擠到只剩 5px 寬，改為兩行版面後為 302px，
  無橫向捲動
- **匯出不錯位**：明細表頭 26 欄、資料列 26 欄一致；彙總同樣一致
