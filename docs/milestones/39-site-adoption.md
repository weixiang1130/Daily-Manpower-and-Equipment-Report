# 節點 39：工地納管（v23.3）

## 背景

新工地上線目前要人工做三件事：

1. 設定頁把工地加進清單
2. 建立該站名單池（分包商／工程師／地點／工種…）
3. 在資料庫填 `sites.project_code`

其中**第 3 項漏做不會報錯**——該站只是「除了管理員以外沒人看得到」。
這是整套權限設定裡最容易發生、又最難察覺的失誤。

同時，人資系統本來就會建立工地別與人員名單，ERP 權限檢視表也已經有
「哪些人在哪個專案掛什麼角色」，這些資料重複人工再輸入一次並不合理。

## 變更內容

設定頁新增「**可納管的工地**」區塊（管理員限定）：

- 按「重新比對 ERP」→ 列出「有本公司人員掛工地角色、但本系統尚未建立」的專案，
  含各專案的工程師／主任人數
- 填好工地顯示名稱 → 按「納管」→ **單一交易內**完成建站、填入 `project_code`、
  把該專案的工程師併入人員池

新增端點：`GET ?candidates=1`（§2.5）與 `op:adoptSite`（§3.11）。

## 設計決策／取捨

### 刻意不做全自動同步

ERP 權限檢視表涵蓋約 **317 個專案**，本系統只需其中十餘個。全自動同步會把大量
無關專案灌進工地選單，反而製造新的整理工作。因此做成「**系統提示、人工確認**」。

### 不需要人資 API 的新介面

原本評估認為需要資訊處提供「依專案列出人員」的人資 API，因為現有的
`GetEmployeeByAD` 只能以 AD 帳號單筆查詢。**實際上 ERP 權限檢視表本身就有
`UserName` 欄**——姓名直接從那裡取即可，人資 API 只在登入判定時使用。
這讓本功能不必等待資訊處開新介面。

### 三件事必須在同一交易

分開做就會出現「建了站但 `project_code` 沒填」——正是這個功能要根除的狀態。

### 人員池併入不覆蓋

重複納管（例如專案新增了人員後再納管一次）只補進尚未存在的姓名，
既有名單與手動加入的人都保留。大小寫視為同值，比照 `op:addOption`。

### 一個專案代碼只能對應一個工地

重複對映會讓權限判定把兩個工地混在一起，故第二次掛同一代碼回 **409**。

### 其餘名單仍由各站自建

分包商、工種、工作地點、機具類型 ERP 沒有，且各站差異大——維持 v17 的
「各站名單池完全隔離」設計，不做預設值。

## 驗證（16 項全過，拋棄式資料庫＋ERP 替身）

- 候選清單：已納管的專案不列出；只有無關角色（如會計）的專案不列出；
  人數統計正確（K02 這類公司別角色不計入）
- 權限：非管理員取候選清單與執行納管皆 403
- 納管：`project_code` 自動填入、3 位人員（含主任）進入人員池、
  無關角色的人不會被帶進來、納管後工地出現在 `scope=all` 的清單、
  該專案從候選清單消失
- 衝突：同一代碼掛到別的工地回 409 並指名已對映的工地
- 冪等：對同一站重複納管 `peopleAdded=0`，且先前手動加入的人員未被覆蓋
- 前端：面板受管理員權限控管；候選列可編輯工地名稱，**送出的是改過的名稱**；
  納管後該列消失
