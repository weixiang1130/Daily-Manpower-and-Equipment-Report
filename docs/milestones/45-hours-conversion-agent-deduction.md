# 節點 45 — 時數換算、0 工單保留工種、代辦扣工上排名（現場回饋五題）

## 背景

現場帶著兩張實體簽單提出五個問題，全部指向同一件事：**系統的「工」是整數/半數的
粗顆粒，而現場的實況是以「小時」計**，於是有一整類單據無法如實回報。

| # | 現場問題 | 根因 |
|---|---|---|
| 1 | 出工不滿 8 小時（0800-1400），只能填 0.5 或 1 | 工數欄 `step="0.5"` |
| 2 | 代扣代辦有時只扣幾小時，不是半天/整天 | 代辦列只有工數欄 |
| 3 | 日間沒進工區、只有夜間加班（0 工＋加班 24 小時） | 勾 0 工會**清空工種** |
| 4 | 代辦扣的量會不會從排名扣掉 | 不會——排名與代辦扣抵是兩張分開的表 |
| 5 | 明細已回報代辦卻空白 | **報表讀錯欄位**（見下，是 bug） |

## 變更內容

### ① 代辦在報表中消失（bug，最優先）

v23 把代辦改存 `rep.agentItems[]`，但**明細與計價彙總沒有跟著改**，仍讀 v22 的
舊制三欄（`vendorDoneWork/Hours/Note`）——那些欄位對 v23 之後的新單永遠是 `null`。
症狀：畫面上填得好好的代辦，匯出給成本部的兩份報表全是空白，**計價彙總的
「廠商代辦工數/時數」對新單一律是 0**。

新增 `agentSummary(rep, kind)` 作為單一來源，明細與計價彙總都改走它；
**新舊不相加**（有 `agentItems` 就以它為準，否則回退舊欄位）——相加會讓被編輯過的
舊單把同一筆代辦算兩次。明細另加一欄「代辦明細(廠商)」把組成攤開（計價紅線 4）。

### ② 工數 ⇄ 時數雙向換算（解 1、2）

工地填**實際工作時數**，系統以 **8 小時＝1 工**換算（保留 4 位小數）。
逐工種列與代辦列各加一個「實際時數／代辦時數」欄，與工數欄雙向連動；
**只存工數**，時數是它的另一種檢視（`work×8` 完全可逆），故資料結構不變。

> 這不是新口徑——排名早就用「加班時數 ÷ 8」折算工數（v21.3），本工沿用同一基準。

`fmt()` 由 2 位小數改為 **4 位**（與 `fmtRank` 統一）：0.625 工若顯示成 0.63，
畫面與匯出的數字就加不回來，成本部對帳會對不上。

### ③ 0 工單保留工種（解 3）

「0 工」原本被當成「整張單沒有內容」——勾選即清空 `typeState`。但夜間才進場的
加班單就是 0 工＋加班時數，工種被清掉後報表只能回退成「（未填工種）」，
**排名與計價都對不到那個工種**。

改為只把**本工歸零、保留工種與加班時數**：0 工時鎖住本工/時數欄，加班欄與代辦列
維持可填（`collectAgentErrors` 本來就分開比對本工與兩段加班，不會誤擋）。

### ④ 代辦扣工進入排名（解 4、5）

依現場裁示，代辦改為**從排名扣抵，且扣抵量與原始量分欄並存**：

- **廠商排名**：新增「代辦扣工／淨工數」，排名依淨工數（機具為「代辦扣抵／淨出工天數」）
- **叫工排名**：代辦扣工按該列工種歸到**簽單責任工程師**，新增「代辦扣工／淨工數」

分欄不合併的理由：只給一個扣完的淨值，看不出組成；而**自辦比例偏高時要查的正是
「哪幾位工程師沒把代辦扣出去」**，需要逐人看得到扣抵量。

## 影響範圍

`frontend/app.js`、`index.html`、`style.css`。**無資料結構變動**——工數欄位型別本就
允許小數，時數為衍生值不落庫，代辦沿用 v23 既有的 `agentItems`。API 合約不變。

## 驗證

以正式資料副本（地端 .NET ＋ LocalDB）實載，並以兩張實體簽單的情境驗算：

| 項目 | 結果 |
|---|---|
| 5 小時換算 | `0.625` 工；`fmt` 顯示 `0.625`（不再截成 0.63）；`workToHours` 可逆回 5 |
| 時數⇄工數連動 | 填時數 5 → 工數 0.625；改工數 0.25 → 時數 2（雙向皆正確） |
| 代辦只扣時數 | 填 3 小時 → 0.375 工；超量代辦仍被擋（2 工 > 本單 1 工） |
| 0 工＋夜間加班 | 工種保留、本工 0、加班 16＋8＝**24 小時**（與單據「技24小時」相符）＝3 工 |
| 代辦扣工（廠商） | 本工 15、總工數 15、代辦扣工 2、**淨工數 13** |
| 代辦扣工（工程師） | 甲：10 工／扣 2／淨 8；乙（無代辦）：5 工／扣 0／淨 5 |
| 明細與計價彙總 | 新制 1.5 工/2 小時、舊制 2 工/4 小時各自正確，合計 3.5/6（不重複計算） |
| 版面 | 排名表 9 欄、明細欄數與表頭一致；無橫向捲軸；console 零錯誤 |
