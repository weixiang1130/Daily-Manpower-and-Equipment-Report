# 節點 46 — 總覽升級為戰情室

## 背景

總覽頁原本只有五張統計卡＋各工地列控表，回答得了「總共有多少」，回答不了
**「現在該追誰」**。實務上成控最需要的兩個問題是：

1. 哪些單**出工日已過卻還沒回報**（跨工地，工地端各自只看得到自己的）
2. 哪些簽單**快逾期或已逾期**（20 天期限）

前者正是長期擱置的「總覽跨工地待回報名單」。

## 變更內容

- **逾期未回報（全部工地）**：出工日 < 今天且仍為「待回報」的單，點工與機具合併、
  依逾期天數由多到少排。逾期 ≥7 天標紅、≥3 天標黃；**整列可點**，直接切到該工地
  並跳到對應清單頁（點工→點工頁、機具→機具頁），把「看到」接上「處理」。
- **關鍵指標卡**新增「逾期未回報」。
- **待繳回簽單提醒**改為依 20 天期限倒數排序，顯示「已逾期 N 天／剩 N 天／尚有 N 天」，
  最急的排最上面（原本只寫「尚未填寫簽單繳回日」，看不出輕重）。
- **本月出工量排名**：工地榜＋分包商榜雙欄長條圖，沿用既有 `hBarChart`。

## 設計決策 / 取捨

- **升級既有總覽而不另開頁籤**：總覽本來就是唯一的跨工地視角，再開一頁會讓
  「看整體」這件事分散在兩個地方。
- **工數口徑一律走 `reportTypeRows()`**（逐工種展開的唯一權威，計價紅線 3）——
  看板自己加總會多出一個與報表對不起來的口徑。加班不折算，因為折算比例是計價議題，
  看板不該自創換算。
- **日期比較用 `Date.UTC` 由年月日三段組出來**，不用 `new Date(字串)` 相減——後者把
  純日期字串當 UTC、把帶時間的字串當本地時間，混用會在 UTC+8 的早晨差整整一天
  （計價紅線 2 的同源問題）。
- **順手修掉 `hBarChart` 的一句假訊息**：頁尾固定寫「完整資料見下方表格」，但戰情室
  只有圖沒有表。新增 `tableBelow` 選項讓它誠實；報表頁行為完全不變。
- 互動一律 `addEventListener`（節點 43 起 CSP 為 `script-src 'self'`，內聯處理器會被擋）。

## 影響範圍

`frontend/app.js`、`index.html`、`style.css`。純讀取與呈現，**不新增任何寫入路徑**、
無資料結構與 API 合約變動。權限沿用既有機制——戰情室看到的資料，本來就是該使用者
有權限看到的資料，只是換個呈現方式。

## 驗證

以正式資料副本（地端 .NET ＋ LocalDB）實載：

- 數字與資料庫直接查詢**完全吻合**：逾期未回報 132（點工）＋208（機具）＝340、
  簽單未繳回 67，與畫面卡片一致
- 點擊切換：點工列→點工頁、機具列→機具頁，工地皆正確切換
- console 零錯誤、零 CSP 違規

## 補強 — 追蹤起算日 2026-08-01（現場回饋）

現場回饋：逾期未回報與待繳回簽單裡「有些是一開始機制還沒全部完善的資料，
所以就會停留在七月」，決定**從八月開始計算，之前的先算了**。

線上實測這批舊資料的規模：

| 面板 | 8/1 之前 | 8/1 起 | 最舊 |
|---|---|---|---|
| 逾期未回報 | **199 筆** | 479 筆 | 2026-07-01 |
| 待繳回簽單 | **46 筆** | 72 筆 | 2026-06-25 |

問題不只是「多了幾筆」——這兩張表都**依逾期天數／期限緊迫度排序**，
所以那批永遠不會有人去補的舊單會**長期霸佔清單最上方**，把真正該追的近期單
擠到看不見。追蹤面板等於失效。

### 變更

- 新增 `DASH_TRACK_SINCE = "2026-08-01"` 與 `inTrackRange(date)`
- 套用到：**逾期未回報**（清單＋卡片）、**待繳回簽單**（清單＋卡片）、
  以及「各工地列控總覽」的**簽單尚未繳回**欄
- 兩張面板的說明文字加上「自 2026-08-01 起算——更早的單是系統機制未完善前的
  舊資料，不列入追蹤（歷程報表仍查得到）」

### 設計決策

- **卡片與清單必須同源**：只濾清單而卡片照算，會出現「卡片說 118、清單只列 72」
  的矛盾；各工地列控的簽單欄同理，否則各站加總對不上卡片。
- **「點工待回報／機具待回報」兩張卡刻意不套用**：那是單純的狀態計數（還沒回報的單
  有幾張），不是「該追誰」的追蹤指標，現場也沒有指定。要一起套用只需在該處加上
  `inTrackRange`。
- **這是畫面層的追蹤起算點，不是刪資料**：歷程報表、匯出、排名一律不受影響，
  舊單查得到也算得到。要調整起算日改一個常數即可。
