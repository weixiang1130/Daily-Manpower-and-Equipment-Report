# 節點 47 — 清單申請人篩選；夜間加班單不再被 0 工防呆擋下

## 背景（現場回饋兩項）

1. **清單找不到自己的單**：多位工程師常同時向同一家廠商叫工，只篩廠商之後
   還要再從一堆單裡找自己的名字。
2. **夜間加班單送不出去**：現場簽單就是「日間無出工、夜間 17-22 進場加班 5 小時」。
   在系統填「出工數 0 ＋ 加班 2＋3」後**無法送出**。

## 第 2 項的真正原因（不是邏輯錯，是文案錯）

節點 45 已經讓 0 工單能保留工種與加班時數，**技術上勾了「0 工確認」就送得出去**
（實測確認）。真正卡住現場的是那個核取方塊的文字：

> 「0 工確認：本日申請後**實際完全無人出工**」

但當天**夜間確實有人加班 5 小時**——等於要填報者勾一個與事實不符的聲明，
所以沒有人敢勾，然後就卡在「實際出工數為 0，請先勾選 0 工確認」的提示裡出不去。

## 變更內容

### ① 清單新增「申請人」篩選（點工／機具皆有）

- 下拉選項由**目前清單實際出現過的申請人**動態組出，不用名單池——名單池會列出
  全站所有人，但清單裡多半只有少數幾位，選了沒資料的等於空篩。
- 選中的值若因其他條件變動而不再存在，自動退回「全部」，不會留著一個空篩。
- 與日期、廠商可複合使用；「清除」一次清掉三個條件；切換工地時一併重置。
- 抽出 `fillFilterSelect()` 供廠商與申請人共用，避免兩份幾乎相同的下拉組裝碼。

### ② 有加班時數時，不再強制勾「0 工確認」

「0 工確認」的用意是攔「**忘了填**」，而**加班時數就是「沒忘記填」的證據**。
因此硬性阻擋只保留在「本工與加班**都是 0**」的情況；日間 0 工＋夜間加班改走
**可確認的警告**（`confirm`），不是無聲通過也不是直接擋死：

> 組工：本日無正常出工，僅有加班 5 小時（夜間進場）——請確認無誤

### ③ 文案修正

- 核取方塊：「0 工確認：本日申請後**完全沒有出工、也沒有加班**，本回報單以 0 工寫入」
- 表單說明補上夜間加班的填法：直接在工種列填出工數 0 ＋ 加班時數即可送出，
  **不需勾 0 工確認**。

## 設計決策 / 取捨

- **不自動勾選核取方塊**：那會讓一個「確認」變成系統代為聲明，失去防呆意義。
- **保留確認視窗而非完全放行**：出工 0 而申請 5 工，差異 -5 是值得看一眼的數字；
  但它是「請確認」不是「不准送」。
- **申請人下拉不用名單池**：理由同上，動態值才不會出現選了沒資料的選項。

## 影響範圍

`frontend/app.js`、`index.html`。**無資料結構、無 API 合約變動**；
`zeroWork` 欄位語意不變（仍代表「完全無出工」），夜間加班單以
`zeroWork=false ＋ 本工 0 ＋ 加班時數` 寫入，比勾 0 工確認更貼近事實。
