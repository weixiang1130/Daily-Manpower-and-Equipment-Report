# 節點 48 — 切換日遷移包：把「完整備份」真的變完整

## 背景

現場問了一個關鍵問題：**雲端這些資料，資訊處上線後要怎麼整批搬過去？**

盤點後發現設定頁的「下載完整備份（JSON）」**名不副實**——它只有 `scope=all`，
而 `scope=all` 依合約**刻意不含**兩樣東西：

| 項目 | 線上實測數量 | 是否在「完整備份」裡 |
|---|---|---|
| 單據＋名單池 | 2.0 MB | ✅ 有 |
| **附件本體** | **828 個、104.8 MB**（掛在 736 張單上） | ❌ **沒有** |
| **行情通報費率書** | 點工 1 季、機具 1 季 | ❌ **沒有** |

只帶那份 JSON 過去，地端會變成「**附件描述資料都在、檔案全部不見**」，
以及「**計價一律查無費率**」。

更麻煩的是移轉工具刻意把 `attachments.file_path` 留成 NULL，註解寫著
「由切換日附件搬運腳本補填」——**但那支腳本並不存在**，部署手冊只寫了
「依 `attachments[].id` 逐一 `GET ?attachment=` 下載」。828 個附件不可能手動搬。

## 變更內容

### ① 新增 `backend/sql/export-cloud-bundle.py`

一次把三樣抓齊，產出可直接交付的遷移包：

```
遷移包_YYYYMMDD/
  data.json              scope=all（工地清單／名單池／全部單據）
  rates.json             行情通報費率書
  attachments/<附件id>   附件本體，**檔名即 attachment_id**
  MANIFEST.json          筆數、附件數與大小、逐檔 SHA256（驗收用）
  匯入說明_給資訊處.md    三步驟
```

- **帳密不寫在檔案裡**，由 `--user/--password` 或 `KG_USER/KG_PASS` 帶入
- **可重複執行**：已存在且大小相符的附件自動跳過，中斷後再跑一次即續傳
- 單檔失敗自動重試 3 次；仍失敗者列進 `MANIFEST.json` 並以非零結束碼結束

### ② 移轉工具直接寫入 `file_path`

`backup-json-to-sql.py` 的 `attachments` INSERT 補上 `file_path = attachment_id`。

地端讀檔是 `Path.Combine(ATTACH_DIR, file_path)`，而匯出的附件**檔名就是
attachment_id**——兩邊對齊之後，資訊處只要把 `attachments/` 複製到 `ATTACH_DIR`，
附件立刻可下載，**不需要事後再回頭 UPDATE 資料庫**。

## 設計決策 / 取捨

- **不做成瀏覽器上的「一鍵下載」**：828 個檔、105 MB 要在前端逐一 fetch 再組 ZIP，
  記憶體與中斷風險都高，而且失敗只能整個重來。這是**一次性的切換日作業**，
  用可續傳、可驗收的腳本才對；設定頁那顆 JSON 備份鈕維持原樣（日常備份仍好用）。
- **檔名直接用 attachment_id**：與地端服務的讀檔路徑天然對齊，省掉一個回填步驟，
  也讓「複製過去就會動」這件事不需要額外說明。
- **附上逐檔 SHA256**：資訊處可據以驗收，不必憑信任。

## 影響範圍

`backend/sql/export-cloud-bundle.py`（新增）、`backup-json-to-sql.py`（附件 INSERT 補一欄）。
**前端與 API 合約完全未變**；`scope=all` 的行為維持原樣（費率書不進去仍是刻意設計）。

## 驗證

以**線上正式資料**跑完整的「匯出 → 匯入 → 開附件」全鏈路：

| 步驟 | 結果 |
|---|---|
| 匯出 | 831 個附件、**104.6 MB**；費率書點工／機具各 1 季；data.json 2.0 MB |
| **續傳** | 中斷後重跑：827 個判定為「已存在」直接跳過、只補下載新增的 1 個 ✅ |
| 轉換 | 8,822 行 SQL；`sites=12／labor=1900／equip=753／attachments=831／agent=102`，**無跳過資料** |
| 匯入 | 全數成功，**831 個附件描述全部帶有 `file_path`** |
| **開附件** | 服務指向遷移包的 `attachments/`，隨機抽 6 個下載——**6/6 HTTP 200，位元組數與宣告大小逐一相符**，型別 PDF／JPEG 正確 |

### 過程中發現並修正的三件事

1. **3 個孤兒附件**（831 中的 3 個，0.36%）：單據有描述資料、雲端卻查無檔案本體，
   多半是當初上傳中斷但單據已存檔。**腳本原本把它們當成「可重試失敗」並要求重跑**，
   但重跑不會變出檔案——已改為與連線失敗分開統計，單獨列在 `MANIFEST.json` 的
   「雲端查無的附件」，且不再讓整個匯出以失敗結束。
2. **匯入說明的指令寫錯**：原本寫成 `python backup-json-to-sql.py data.json > import.sql`，
   但該工具吃**兩個參數**，用 `>` 只會得到一行用法說明、接著 sqlcmd 報語法錯誤。
   自己照著文件跑才踩到，已修正並在說明中加註。
3. 測試時另有兩次「假警報」——`curl` 傳中文工地名的編碼問題造成 404。改用 Python
   以 UTF-8 呼叫即 6/6 正常，**與系統無關**，一併記在此以免日後重蹈。

> 測試全程使用拋棄式資料庫 `KG_MIGTEST`，驗畢已刪除；既有的 `KG_AUDIT_STAGING` 未受影響。
