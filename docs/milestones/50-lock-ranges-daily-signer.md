# 節點 50：鎖檔區間 ＋ 月租逐日簽認工程師 ＋ 逐日內容欄版面（v24.7）

## 背景

月租機具（節點 49）上線後，工地端試用回報三件事：

1. **逐日紀錄的「工作內容」格子不好登打**——只有 280px，擠在同一行的中間。
   使用者甚至不確定當日內容到底該打在這裡、還是打在下方的「實際工作內容」。
2. **月租的「簽單責任工程師」只能填一位**，但整個租期一張單，
   每天在簽單上簽名的不見得是同一個人，沒有欄位放得下。
3. **需要鎖檔機制**：結算後把一段期間的資料凍結，工地端不可再申請與回報；
   要能各工地獨立設定、能再打開、時間精細到年/月/日/時，
   而且**可以先設定、時間到才生效**（例：現在設定，8/20 17:00 起把 7/1～8/17 鎖住）。

## 決策與做法

### ① 當日內容就填在逐日紀錄（版面問題不是資料模型問題）

逐日紀錄本來就是月租單的施工軌跡（取代現場手寫的「包月-1、-2」），
當日內容填在這裡是對的；下方「實際工作內容」是整張單的摘要，月租可留空。
使用者會問，是因為版面讓人以為它不是主要欄位——所以改的是版面不是欄位歸屬：

- 新增列：內容欄**獨佔一整行**（280px → 771px），日期/時數/簽認/按鈕留在上一行
- 逐日列：`.att-fields` 原本是 `flex:0 1 auto`，只佔內容寬、列尾空一大片而內容欄被壓成
  201px。改成可 grow 後 → 697px
- 窄視窗（<900px）：`.att-fields` 預設 `nowrap`，三欄擠一列會把內容欄壓到 18px，
  加 media query 讓它換行、內容欄自成一行
- 加一筆之後**日期自動 +1 天、簽認人不清空**——連續數日通常同一人，
  可以「打內容 → Enter → 打內容 → Enter」一路登打
- 提示文字直接寫明「當日工作內容填這裡即可，下方『實際工作內容』是整張單的摘要」

### ② 每日簽認工程師：逐日一欄，單頭 checker 語意改為「本張單的覆核者」

`usageLog[]` 加 `signer`（選填，datalist 帶出該站人員名單）。
單頭的 `checker` 不動——月租時它的意思是「彙整對帳的覆核工程師」，
表單上直接用提示文字講清楚，避免使用者以為系統要他挑一個代表人。
在場提示會列出這張單出現過的所有簽認人。

### ③ 鎖檔：從「一個切點」擴充成「可累積的區間清單」

舊機制是 `config.lockDate`＝「這天含以前全鎖」。實務上結算是一段一段來的，
而且需要緩衝期，所以改成：

```
lockRanges: [{ id, from, to, effectiveAt, enabled, note }]
```

- `from`/`to`＝鎖定的**出工日期**區間（含兩端），單邊可空
- `effectiveAt`＝**本地**生效時刻（`datetime-local`，年/月/日/時分），空＝立即生效
- `enabled`＝隨時可關；解鎖用停用而不是刪除，下個月要再鎖直接打開
- 各工地獨立（存該站 config）；管理員一律不受限
- `lockDate` 保留讀取相容，舊資料不會因改版突然解鎖

設定頁的規則列有三種狀態（鎖定中／預約中／已停用），各有左邊條顏色，
但**狀態文字一律直接寫出來**——顏色不是唯一線索。
另加「套用到全部工地」：結算是全公司同時做的，逐站切換設定既慢又容易漏。

**強制點**：前端 9 處（申請/回報的新增、修改、刪除）沿用既有的 `isLockedDate()`，
判定改走 `lockReason()` 後全部自動涵蓋，呼叫點一行沒動。
**地端後端再擋一次**（`op:record`／`op:deleteRecord` → 403 `{"error":"locked"}`）——
前端擋的是誤操作，結算後的資料凍結是實質控制，只靠前端等於「按 F12 就能改已結算的月份」。

> ⚠ 修改既有單據時**新舊日期都要查**。只查送進來的新日期的話，
> 把一張已鎖日期的單改成未鎖日期就能整張搬出鎖定區間，鎖了等於沒鎖。
> 這條在實測案例 (e) 驗證過。

## 順手補掉的既有缺口

盤點資料庫落地時發現節點 49（月租）只做到前端與雲端，**地端遷移鏈是斷的**：

| 缺口 | 影響 | 處理 |
|---|---|---|
| `backup-json-to-sql.py` 沒有 `billing`／`rentFrom`／`rentTo` | 切換日一遷移，15 張月租單全部退化成日租、租期消失 | 補上；舊單缺鍵補預設「日租」（欄位 NOT NULL，送 NULL 會整包回滾） |
| 同上，沒有 `onSiteDays`／`equip_usage_log` | 月租的在場天數與施工軌跡整批遺失 | 補上；同日重複取首見（撞 UQ 會整包回滾） |
| 機具匯出沒有逐日紀錄欄 | 月租的施工軌跡與逐日簽認在 CSV 裡查不到 | 新增「逐日使用紀錄(月租)」欄 |
| `docs/API-CONTRACT.md` 沒有 §4.4 的月租欄位與 `usageLog` | 後端重寫者不知道要實作 | 補齊 |
| 兩支 Python 工具在中文 Windows 主控台會炸 | `⚠` 編不進 cp950 → `UnicodeEncodeError` ＋非零結束碼，檔案其實已寫好卻看起來像失敗 | stdout/stderr 改 UTF-8 並容錯 |

## 驗證

**前端**（本機伺服器＋注入狀態）
- 鎖檔判定：生效前全不鎖 → 生效後 7/1～8/17 鎖、邊界 6/30 與 8/18 不鎖 → 停用即解鎖 →
  管理員不受限（但仍看得到落在哪個區間）
- 設定頁：三種狀態各自的文字與顏色、防呆（兩側全空／起日晚於迄日）、加入後輸入清空與排序、停用切換
- 逐日紀錄：日期自動遞增、簽認人保留、內容清空、租期外擋下、同日重複擋下、datalist 帶出人員名單
- 版面：內容欄 280→771px（新增列）、201→697px（逐日列）、375px 窄視窗 18→243px，無橫向溢出

**資料庫**（拋棄式 LocalDB，未碰 STAGING/TEST）
- 新版 DDL 建庫 → 以正式資料備份（12 站／1,065 機具單）跑遷移工具 → 匯入結束碼 0

- ALTER 腳本：舊版 DDL 建庫（18 表）→ 升級 → 19 表＋`signer` 欄；重複執行結束碼 0
