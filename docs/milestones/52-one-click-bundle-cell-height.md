# 節點 52：一鍵切換日遷移包；表格儲存格限高（v24.9）

## 一、一鍵切換日遷移包

### 背景

現場的要求是：「從現有公有雲上下載整包打包，資訊處部署後直接放上去，
讓工地使用者不需要重新登打資料。」

原本已有完整的遷移機制（節點 48 的 `backend/sql/export-cloud-bundle.py`），
但它是**由成本管理部在切換日跑的命令列腳本**，不是系統裡的一個按鈕。
而系統裡那顆按鈕（「下載完整備份（JSON）」）依合約**不含附件本體與費率書**——
名稱讀起來像完整備份，切換日誤用會讓 831 個附件（104.6 MB）整批遺失
（該按鈕已於節點 48 補強正名，本節點再補上真正的一鍵版本）。

### 做法

設定頁 → 資料管理新增「📦 切換日遷移包（含附件・給資訊處）」，管理員限定。
一次抓齊三樣並打包成 zip：

```
點工機具_切換日遷移包_YYYY-MM-DD.zip
  data.json              scope=all（工地清單／名單池／全部單據）
  rates.json             行情通報費率書
  MANIFEST.json          筆數、附件數與大小、逐檔 SHA256（驗收用）
  匯入說明_給資訊處.md    三步驟
  attachments/<附件id>   附件本體，檔名即 attachment_id
```

**產出結構與 `export-cloud-bundle.py` 完全一致**——資訊處的匯入步驟、
`backup-json-to-sql.py` 寫入的 `file_path` 都依賴它。兩條路徑擇一即可。

### 為什麼自己寫 ZIP：其實不用寫

第一版我另外寫了一套 CRC32 ＋ ZIP 封裝，**寫完才發現 app.js 裡早就有一套**
（v19.5 的 xlsx 產生器——xlsx 本身就是 zip）。已刪掉重複實作，改用既有的
`zipStore()`，只把它擴充成「`data` 可為字串或 Uint8Array」：

> ⚠ 二進位一定要原樣寫入。原本 `enc.encode(e.data)` 只吃字串，
> 附件若先轉字串再編碼，非 UTF-8 位元組會變成 U+FFFD，JPEG／PDF 整個壞掉。

### 兩個實作上的坑

- **每個附件要用它自己的工地名**。既有的 `attUrl()` 走 `MASTER.currentSite`，
  對全量匯出是錯的——別站的附件會查無。
- **雜湊失敗不可算成下載失敗**。第一版把 `sha256Hex()` 的例外和下載例外一起接，
  結果附件明明已經在 zip 裡卻被記成「失敗」，`exported` 也與實際內容對不上，
  資訊處會以為要重跑。已拆開：下載失敗才計入 missing／failed，
  雜湊算不出來只是 MANIFEST 少一個欄位。

### 驗證

**ZIP 格式**（下載後以 Python `zipfile` 開啟）
- 逐檔 CRC 驗證通過；中文檔名正確（GP flag bit 11 有設）
- 二進位原樣：含 `0x80/0x90/0xA0/0xB0` 等非 UTF-8 位元組的檔案位元組完全相同
- MANIFEST 的 SHA-256 與實際檔案內容相符

**完整流程**（模擬兩個工地、單據附件＋稽核附件、一個 404 孤兒）
- 附件枚舉正確：5 個（含稽核底下的），各帶自己的工地名
- 預期 5／實際匯出 4／雲端查無 1／失敗 0
- 404 孤兒歸到 `missing`（重跑也不會有）而非 `failed`（可重試），兩者分開列

## 二、表格儲存格限高

### 背景

現場回饋「各種表格的欄位顯示要重新排版、要可以清楚顯示」。先盤點再改。

### 盤點（以正式資料 2,201 張點工＋1,042 張機具，用程式自己的報表產生器跑）

**欄寬登記是乾淨的**：`COL_W` 66 個登記項，實際使用的表頭沒有漏登記的
（排名表走自己的 `.rank-table` CSS，計價面板已下架）。

**真正的問題是列高**。固定欄寬下長文字只能往下折，而**同一列的高度由最長那一欄決定**：

| 欄位 | 欄寬 | 正式資料最長 | 折成 |
|---|---|---|---|
| 逐日使用紀錄(月租) | 260px | **1,446 字** | **85 行** |
| 現場查核回饋 | 220px | 302 字 | ~11 行 |
| 工作內容 | 120px | 167 字 | ~14 行 |
| 廠商代辦備註 | 100px | 117 字 | ~19 行 |

一張單有這種內容，整列就被拉到 1,359px 高，旁邊二十幾個只有一行字的欄位
全被撐開——表格變成沒法掃讀的長條。**這是我在節點 50 加「逐日使用紀錄」欄時
種下的**：把一整個月的施工日誌塞進一個儲存格。

### 做法：限高，不是逐欄調寬

儲存格內容包一層 `.cellbox` 並限高 `7.5em`、超出內捲。

選這個而不是逐欄加寬，理由是**加寬治不好**：表格已經 2,500／2,918px 寬、
視窗只有 1,265px，本來就要橫捲兩倍；再加寬只會更糟，而 1,446 字不管給多寬都會很高。
限高是對「列高由最長欄決定」這個機制本身下手，一次涵蓋所有長文字欄。

- **不改欄寬、不改內容**；匯出仍是全量全文（計價紅線 3），實測匯出字串仍為 1,446 字
- 列印時解除限高，否則紙本會把捲軸外的內容整段吃掉

### 驗證（正式資料）

| | 最矮 | 中位 | 最高 |
|---|---|---|---|
| 點工明細（329 列） | 39px | 96px | 120px |
| 機具明細（284 列） | 39px | 59px | 120px |

最壞情況那一列：**1,359px → 120px（改善 11.3 倍）**，該格可內捲。
計價彙總（共用同一個渲染函式）正常，列高同樣收斂在 120px。

### 盤點順帶查到、但不是問題的

- **代辦明細欄出現 `undefined`**：是我測試資料把欄位名寫成 `workType`
  （合約是 `type`）。正式資料 280 筆代辦列**全部都有 `type`**，畫面不會出現 undefined
- **`根基自辦工數/時數/備註` 三欄近乎全空**（v23 起表單已移除，2,201 張裡只有 1 筆有值），
  合計佔寬 224px。要不要從畫面移除（匯出保留）**待裁示**——那會改變成本部看到的欄位
