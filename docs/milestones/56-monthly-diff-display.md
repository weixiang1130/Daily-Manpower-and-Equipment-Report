# 節點 56 — 月租單不再被標「未填預定」

**日期**：2026-08-24　**範圍**：僅 `frontend/app.js`（顯示層，資料不動、後端不動）
**來源**：工地端實際回報（某工地的月租機具單）

## 問題

月租申請單**設計上就不填**預定使用時數（送出時 `plannedHours` 一律存 `null`——
「每台每日預定幾小時」對整個租期一張的單沒有意義）。但差異的顯示層只認
`diff == null` 一種狀態，於是每一張月租單：

- 回報表單的差異欄顯示「（申請單未填預定時數）」
- 機具清單與歷程報表的差異欄顯示「未填預定」標籤
- 清單的出工天數欄顯示 `rep.days||0` ＝ **0**（月租的天數在 `onSiteDays`，不在 `days`）

「不適用」被誤標成「漏填」：現場以為自己開單開錯而回頭改申請單，
而事實上他們什麼都沒做錯。

## 修法（四處，全在顯示層）

| 位置 | 改後 |
|---|---|
| 回報表單差異欄 | 月租 → 「—（月租單不比較預定時數）」（在 null 檢查**之前**分流，順序反了永遠落入舊訊息） |
| 機具清單差異欄 | 月租已回報 → 中性「月租」標籤（title 註明不比較）；待回報維持「—」 |
| 清單出工天數欄 | 改用既有 `equipOnSiteDays(x)`——月租＝在場天數、日租＝`rep.days`（**同值，行為不變**），與排名同一口徑 |
| CSV 差異欄 | 月租寫「月租」而非留白——成本部在 CSV 上要分得出「不適用」與「日租漏填預定」 |

資料層完全不動：月租的 `diff` 本來就存 `null`，是對的。

## 驗證（瀏覽器實測）

| 情境 | 清單差異 | 清單天數 | CSV 差異 |
|---|---|---|---|
| 月租已回報（在場 1 天） | 月租 | **1**（原本 0） | 月租 |
| 日租、申請未填預定 | 未填預定（不變） | 1 | ""（不變） |
| 日租、差異 0 | 相符（不變） | 1 | 0（不變） |
| 月租待回報 | —（不變） | — | "" |

表單：月租 → 「—（月租單不比較預定時數）」。日租三態（未填預定／未勾到場／算式）不變。
