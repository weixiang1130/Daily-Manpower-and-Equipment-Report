# 節點 57 — 已回報單刪除限管理員：補上伺服器端把關

**日期**：2026-08-24　**範圍**：僅 `backend/onprem/dotnet/Program.cs`　**來源**：交付前資安審查

## 問題

「已回報的單據是計價依據，僅限管理員刪除」這條規則原本**只有前端在擋**
（清單對非管理員隱藏刪除鈕＋toast）。直接呼叫 `op:deleteRecord` 就繞過去了——
與鎖檔（節點 50）修正前是同一類「前端管控＝按 F12 可破」的缺口：
任何看得到該工地的使用者，都能刪掉自己站上已回報的單據，而那是成本部的計價依據。

## 修法

與 `LockGuard` 同一層新增 `ReportedDeleteGuard`：非管理員對**存在且已回報**的單據
執行 `op:deleteRecord` → 403（訊息與前端一致）。三個邊界刻意維持原行為：

- 形狀錯誤／查無工地／查無單據 → 交還 `OpDeleteRecord`（400／冪等 200）
- 管理員不受限（與鎖檔一致——規則就是他在執行）
- `Auth:Mode=Off` 時不介入（authz 為 null，維持過渡期行為）

## 驗證（拋棄式庫＋發佈版執行檔，測畢 DROP）

| 案例 | 結果 |
|---|---|
| 非管理員刪「已回報」 | ✅ 403，單據原封不動 |
| 非管理員刪「待回報」 | ✅ 200（自刪權維持） |
| 管理員刪「已回報」 | ✅ 200 |
| 非管理員刪不存在的 id | ✅ 200（冪等不變） |
