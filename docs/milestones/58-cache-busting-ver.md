# 節點 58 — 靜態檔引用加 ?ver= 快取參數（資訊處建議）

**日期**：2026-08-25　**範圍**：僅 `frontend/index.html`（3 個引用）　**來源**：資訊處部署後建議

## 背景

地端伺服器對靜態檔不送 `Cache-Control`（ASP.NET Core `UseStaticFiles` 預設行為），
`index.html` 引用又寫死檔名——換版後使用者端靠啟發式快取，**可能繼續跑舊檔且無感**。
v24.13 部署當天實測：`app.js` 已換新，但已開過系統的使用者不重新整理就拿不到。

資訊處建議在引用加版本參數強制更新，採納。

## 做法

`style.css`／`config.local.js`／`app.js` 三個引用一律帶 `?ver=YYYYMMDDNN`（NN＝當日流水序），
本次起始值 `2026082501`。檔內留註解指向 CLAUDE.md 規範。

**維護規則（已寫入 CLAUDE.md 前端要點）**：日後凡改 js/css，`index.html` 的對應參數
必須隨該次改動一起進位——只改檔不進版＝使用者吃舊快取，等於沒部署。

## 驗證

本機靜態伺服器實載：三個引用均帶 `?ver=2026082501`，`app.js` 正常執行、CSS 正常套用
（靜態伺服器對 query string 透明，不影響檔案服務）。
