# 節點 59：總覽改版——追蹤提醒合併＋20 天期限口徑＋排名上移（2026-08-28）

## 背景

使用者盤點總覽頁提出四點：①逾期未回報的天數無限增長（已 27 天且每日 +1），
超過 20 天（簽單不予採計）的死單永遠置頂；②月租機具的警示與回報機制要跟上
節點 49 補強四的「租期迄日」基準；③「逾期未回報」與「待繳回簽單提醒」功能重複；
④本月出工量排名要上移到更醒目的位置。

MAX 盤點另抓到三個既有缺陷：
- **簽單追蹤漏掉全部機具單**——`pendingSign` 只掃 `allLabor`，機具回報明明有
  簽單繳回日欄位，卡片／列控總覽／提醒清單三處永遠是 0
- **月租單租期未結束就被列為逾期未回報**——逾期判定用出工日（＝租期首日），
  租期進行中即顯示「逾期 N 天」（與補強四同類的基準遺漏，實測畫面「逾期 7 天」
  的單租期其實到 9/30）
- **各工地列控總覽的簽單欄自成一套口徑**（labor-only、無期限概念），改版後會與
  卡片打架（v24.6 教訓：卡片與清單必須同一份資料）

## 決策

1. **單一口徑 `trackLeftDays(rec, today)`**：不論「未回報」還是「簽單未繳」，
   追的都是同一個 20 天窗口——基準日（`signBaseDate`：月租＝租期迄日、
   其餘＝出工日）＋20 天。卡片、追蹤清單、列控總覽三個消費端都走這裡。
2. **兩面板合併為「追蹤提醒」**：統一「剩 N 天」倒數、剩最少的排最前
   （取代「逾期天數多在前」的死單置頂）；列標示「未回報／簽單未繳」型別；
   點工＋機具都列；列可點擊跳轉（原簽單提醒清單沒有動線）。
3. **超過 20 天不列入**：left<0 的單不進清單與卡片，只在清單尾端彙總一行
   ——簽單已逾期不予採計，追回無實益；歷程報表照樣查得到。
4. **排名上移**：概況卡之後的第一個面板。
5. **月租回報不受 20 天限制（實測確認，非程式變更）**：租期迄日＋20 已過的
   月租單，回報本身照常可送（繳回日留空或填期限內日期都 200）；只有
   「簽單繳回日」欄位受期限限制（填今天→400 逾期不予採計，訊息如實顯示）。

  ＝逾期未回報 449＋簽單未繳 72；超過 20 天彙總 84 張獨立成行
- 月租三態抽查：租期至 9/30 的待回報單**不再列逾期**（舊版顯示逾期 7 天）；
  租期 7 月者 left=-9 進彙總；租期 8/26 者以租期迄日起算 left=18 進清單
