# 節點 62：代辦工種彙總表（責任歸屬廠商×工種）（2026-09-04）

## 背景

工地回饋：代辦的工數在匯出總表只有**合計**——例如一張單代辦了
打石工 2 工＋技術工 6 工＋組工 10 工，計價彙總的「廠商代辦工數」只看得到 18 工。
成本部扣款時**各工種費率不同**，只有合計會不知道扣的是什麼工種。

這正是計價紅線 4「報表要讓人看見組成」。資料層面 v23 起代辦就是逐筆填的
（`agentItems[]` 每列都有廠商＋工種＋工數＋加班兩段），只是彙總時被加總壓扁。

兩個候選方案：① 在計價彙總加一欄文字組成；② 另出一張「廠商×工種」結構化表。
專案負責人裁示採 **②**（「做乾淨徹底一點，一勞永逸」）——結構化列比文字串
可直接拉樞紐、對費率表，不用再拆字串。

## 設計

**一份彙總邏輯、三個出口**（口徑唯一，數字不會各長各的）：

- `buildAgentTypeSummary(recs)`：以「責任歸屬廠商×工種」為鍵逐列歸戶，
  累計 代辦工數／加班(前2h)／加班(3h起)／列數／來源廠商（本單廠商）。
  **母體由呼叫端傳入**——排名頁＝期間內全部已回報；計價彙總匯出＝跟隨當下篩選。
- 出口一：**廠商排名頁第四張表**「代辦工種彙總」（畫面＋既有 CSV 匯出加第四區塊）
- 出口二：**點工計價彙總 xlsx 的第二張工作表**——成本部本來就用這個檔對帳，
  分工種明細直接進同一個檔案。期間內完全沒有代辦時**不出這張表**
  （空表比沒有表更讓人疑惑）

欄位設計的三個講究：

1. **加班兩段分開列**——前 2 小時與第 3 小時起費率不同（計價紅線 1），
   合併就沒辦法按段扣款
2. **折算工數＝代辦工數＋(前2h＋3h起)÷8**——與點工榜「代辦扣工」同一換算
   （`OT_PER_UNIT`），兩張表可互相對數
3. **「來源廠商」欄**——這些工是向誰叫的（本單廠商），追查時不用回翻明細

## 邊界處理

- **v23 前舊制單**（只有三欄合計、責任廠商埋在自由文字備註）：獨立成
  「（v23 前舊制單）／（未分工種）」一列。不能假裝知道工種，也不能靜靜丟掉
  ——丟掉的話總數會對不上計價彙總的「廠商代辦工數」。舊制「代辦時數」未分段，
  不列入加班兩欄（表下註解明講）。
- **機具代辦不列入**：機具的代辦綁廠商層級、本無工種可分（合約 §4.10），
  其數量已在機具榜「代辦扣抵」欄與代辦扣抵彙總呈現。
- 順手把排名頁兩處相同字面的統計母體 filter 收斂成 `rankedRecs(kind)`
  （第四張表進來後同一 filter 就有三份了）。

## 補強（2026-09-04・MAX code review ＋ 資安複查，同日修畢）

初版驗證通過後，以正式資料快照全庫對帳＋惡意輸入實測再審一輪，抓到並修正下列問題
（`?ver=2026090402`）：

1. **舊制「代辦時數」被靜默丟掉（最嚴重）**：初版只在觸發條件裡讀 `vendorDoneHours`、
   從未累加——正式資料實測與計價彙總的「廠商代辦時數」差 99 小時，且全集中在單一工地。
   ⚠ 修法**不是**把時數折成工數加進折算工數：舊制時數的語意無法機器判定
   （有的單是工數×8 的重複表達、有的只填時數），硬折會把重複表達的單算成兩倍。
   改為單獨一欄「時數(未分段)」讓數字可見、可對帳，折算工數維持只計工數，表下註解明講。
   同時「只填時數沒填工數」的舊制單（正式庫實有兩筆）不再變成全零幽靈列。
2. **表下註解的口徑聲明是錯的**：原寫「與點工榜『代辦扣工』同一換算」，但該榜對舊制單
   根本沒有 fallback（一律 0），兩個合計本來就會差一個舊制量。已改寫為「對數時先扣除
   舊制列」。（點工榜行為不動——它的口徑自 v24 一貫如此。）
3. **同名檔案有時 1 張表、有時 2 張表**：xlsx 第二張工作表改為**無條件出現**，
   無資料時印一列「（期間 無代辦資料）」——寫死 `Sheets(2)` 的巨集才不會間歇爆錯，
   也與 CSV 空區塊的表達一致。
4. **新表加「期間」首欄**（與計價彙總同型）——逐月匯出疊在一起不失去月份歸屬。
5. **廠商排名 CSV 檔名**：改為只標期間＋匯出日（原本會把根本沒套用的廠商／內容／
   工程師篩選寫進檔名，收檔的人會以為內容篩過了；匯出日也讓改版前後的檔案分得開）。
6. **歸戶鍵撞鍵**：`${vendor}|${type}` 字串串接在廠商名含「|」時會把工數併到別家，
   改 `JSON.stringify([vendor, type])`。（`laborBindKey` 同慣例但其鍵已存入各站
   config，不能順手改，另案處理。）
7. **收 `kind` 參數**（與 `agentSummary`／`agentDeductions` 同慣例）：非 `"labor"`
   一律回空——機具代辦是 `{vendor, qty}`，硬算不報錯、只會產出全零假表。
8. **缺廠商／工種的列改佔位**「（未填廠商）／（未填工種）」：原本畫面印字面
   `undefined`、xlsx 卻印空白（兩出口不一致），且空值進 sort 的 `localeCompare`
   會 TypeError 讓整頁排名（含正常的三張表）全部空白。sort 一併加 `|| ""` 防呆。
9. **舊制警示列固定排最後**：「（」是全形括號、CLDR 排序在中文之前，混入排序會
   佔據表首（讀者視為最大值的位置）。
10. 註解與本文件的「三處」更正為「兩處」（實際只收斂兩處相同 filter）。

補強後重驗（同前之注入法）：時數對帳 Σ(前2h＋3h起＋未分段)＝計價彙總廠商代辦時數
（38＝38）✅、工數對帳 17＝17 ✅、撞鍵兩列正確分離 ✅、機具傳入／漏傳 kind 均回空 ✅、
舊制列殿後 ✅、xlsx 空狀態仍兩張表＋說明列 ✅、console 零 JS 錯誤 ✅。

資安複查（獨立代理、逐路徑證據鏈）：DOM 全走 `esc()`、CSV 全走 `csvCell`（公式注入
前置 `'` 對自由文字廠商名生效）、xlsx inlineStr 無法夾帶公式與 XML、無跨站資料暴露、
文件去識別化合規——**無新增可利用弱點**。
