# 節點 64：機具回報「引導人員」＋工程師機具使用榜（2026-09-10）

## 背景

工地反映：堆高機實務上通常配一位**引導（指揮）人員**隨車作業，但機具單上完全沒有
人員欄位，這筆人力只能塞備註或漏記。需求原文的口徑是「1天／前2小時加班／2小時後加班」
——正是**點工的分段規則**：引導人員是「人」，計價走點工費率，前 2 小時與第 3 小時起
費率不同，必須分段記。這個口徑是對的，不是現場想複雜了。

同時要求新增「**工程師使用機具的排名**」——機具榜只看得到「哪家廠商供了多少」，
看不到「哪位工程師叫了多少機具」，與點工的叫工排名互為對照。

## 決策（使用者逐項裁示）

1. **只記數字＋一格選填備註**，不記引導人員姓名（記名字拖慢填單）。
2. **適用全部機具類型**（選填、預設空白），不鎖堆高機——機具類型是各站名單池的
   自由文字（「堆高機」「堆高機3.5t」都可能），用字串鎖型號必漏；吊車也常配指揮/吊掛手。
3. **機具榜加獨立一欄呈現**，不併入在場天數——人·工與台·日是不同單位。

## 口徑（計價紅線）

- 欄位：`guideWork`（出工數，工）／`guideOt2`（加班前 2 小時）／`guideOtOver`
  （加班第 3 小時起）／`guideNote`（備註）。
- **null＝未填、0＝真的 0**（同 `diff` 的理由）：報表據此決定留白或印 0。
  前端空白送 null、載回時 null 顯示空白；DB 四欄可空、**不設 DEFAULT 0**。
- 引導三欄與機具本身的天數／加班**分欄並存、永不相加**（單位不同），
  三個出口一致：機具明細（歷程報表＋CSV 四欄）、機具計價彙總（三欄）、
  機具榜「引導人員(工)」獨立欄（不進淨值）。
- 加班分段規則同點工（前 2h 先計、溢入第 3h 起），送出前警告與點工同款：
  「填了第 3 小時起但前 2 小時為 0」。
- **0 使用單不清空引導欄位**（機具未使用當日人員仍可能到場待命），
  僅跳確認警告——與 `agentItems`（0 使用清空）刻意不同，已記註解。

## 工程師機具使用榜

`buildEngineerEquipRanking()`：分組鍵＝**申請人**，其餘口徑與機具榜完全同源
（在場天數＝日租出工天數／月租逐日紀錄筆數；月租台·月另計；引導人員獨立欄；
僅計已回報、跟隨期間篩選）。畫面排在機具廠商排名之後（附長條圖）；
**CSV 固定附在第五區塊（最後）**——既有四區塊位置不能動，收檔端靠位置取數
（節點 62 教訓）。

## 實作

- `DB-SCHEMA.sql`：`equip_reports` 四欄＋`v_equip_detail`／`v_equip_pricing_summary` 帶欄。
- `ALTER-v2416-guide-personnel.sql`：已建庫者的升級腳本（存在性檢查、可重複執行；
  VIEW 用 CREATE OR ALTER 重建，內容與 DB-SCHEMA 逐字一致）。
- `Program.cs`：INSERT 四欄（`Dx`——可空，**不可用 D0**，會把未填壓成 0）＋
  scope 讀取 JSON 對映四鍵。讀取查詢是 `SELECT rp.*`，欄位自動帶出。
- `backup-json-to-sql.py`：INSERT 對映同步（合約與 DDL 是同一件事的兩面）。
- `app.js`／`index.html`：回報表單四欄（加班時數之後）、送出（空白→null）、
  載回、警告（分段順序／高於常態／0 使用確認）、歷程報表四欄、計價彙總三欄、
  機具榜一欄、工程師榜（畫面＋CSV 第五區塊）。`?ver=2026091001`。
- 雲端 `api.mjs` 與可攜式 `server.mjs` 存整包 JSON，無需改動。
